# ResetWatch 多端产品界面设计 v1

设计日期：2026-10-21。产品基线：main `8d72fc6a3d30805c57463238ebe541ad9806c44e`。

## 交付边界

本目录是界面设计、可交互 HTML 原型与未来产品蓝图，不替换现有 `/workbench`，不修改数据库、订阅、告警引擎或移动端生产配置。所有事件、英文帖子、历史记录、截止与通知状态都是明确标注的模拟数据。没有冒充 Tibo 真实原帖，没有伪造 X 永久链接、认证标识、互动量或账户到账。设计可用不等于产品上线。

将 `index.html` 保存后用现代浏览器打开，不需要 npm 安装或网络。页面顶部可切换网页、微信、iOS、Android、HarmonyOS、未来产品、设计规范七种视图；明暗主题、九种事件状态可切换。原生外壳均为浏览器模拟，不是系统组件本身。

## 产品定位与用户分工

品牌名沿用 ResetWatch，首发主题是 Tibo / Codex / ChatGPT Work 额度情报。品牌主张是“先看到公告，再安排工作”，不承诺预测未来 Reset，不承诺秒级送达。

普通用户：看事件、读证据、核对时间、管理提醒、查看历史。运营人员：校对来源、整理事件、维护告警、审查传播稿、追踪渠道与回执。不能把整个内容管理后台复制到小程序首页。

未来可以扩展 AI 用量情报，但其他供应商、个人额度、团队空间、原生小组件都是概念，不能展示为已经接入。首发不采集 OpenAI 密码、会话令牌或账号凭据。

## 信息架构

### 网页工作台

| 页面 ID | 页面 | 核心任务 | 与现有产品的关系 |
|---|---|---|---|
| W01 | 实时事件 | 当前事件、原帖翻页、双时区、行动窗口 | 延续既有卡片与 API |
| W02 | 证据与历史 | 历史比较、原帖校对入口、来源等级 | 归组现有历史和校对，不删除原功能 |
| W03 | 告警与送达 | 事件类型、提醒偏好、渠道、可用回执 | 新设计，需后端与通道接入 |
| W04 | 内容工作室 | 告警优先、独立传播稿、未发布状态 | 延续原有草稿，未来接入发布审计 |
| W05 | 产品设置 | 时区、隐私、主题、客户端就绪度 | 延续已有客户端状态并归组 |

### 移动端

微信：动态 / 历史 / 我的；提醒设置从“我的”进入，减少轻用户入口。iOS、Android、HarmonyOS：动态 / 历史 / 提醒 / 我的，保持稳定的四个主入口。生产接入时将现有客户端“文案”迁为运营权限入口或内容分享能力，而不是暴露后台编辑器给所有访客。

事件详情与来源卡片是共用组件，不随平台重写事件语义。平台差异限于导航、字号、安全区域、系统授权、辅助功能、背景与多窗口生命周期。

## 核心视觉规范

沿用现有森林绿品牌：品牌 `#14624d`，侧栏 `#122d27`，雾白背景 `#f2f5f3`，正文 `#182d29`，次级 `#576d66`。琥珀提示参考窗口，信息蓝标传播/Banked，红色提示故障，不用大红色倒计时制造恐慌。深色主题用独立配色，不能直接反色。

布局间距采用 4/8/12/16/24/32；卡片圆角 16–20；主标题 28–32，移动标题 24–30，主要正文 14–16，次级 12–13。原型中的设备缩略展示含更小的辅助字，生产端必须按系统可访问性要求验证，不能以缩略原型字号作为可读性合格证据。

操作区域设计目标：最少 44 CSS 像素，安卓目标 48dp；小圆点保持可点外框，不能只扩大可见标记。常规正文对比度目标 4.5:1；大字和 UI 边界按对应标准单独检查。颜色不是唯一状态提示。

## 必须保留的 X 卡片契约

每页一个独立边框，顶部 TS 占位、Tibo、@thsottiaux、X 标记、北京时间与美国太平洋当地时间。不要伪造蓝标或互动计数。正文左解释、中中文译文、右英文；三栏顺序不变。手机允许内部横向浏览，不缩成难读的三列。卡片顶部手势翻页与正文横向阅读分离；键盘方向键仅在卡片自身聚焦时翻页，不劫持编辑框或阅读滚动。

解释层级：先“重置最晚时间：北京时间 日期 时分”，接“换算依据 / 参考最晚截止 / 可能提前”，再放通俗说明。真实 EOD 场景必须标注 PDT/PST 及原帖当地日期；本设计的模拟数据没有 EOD 语句，不能硬加 PDT 依据。

底部：当前北京时间、距这条推文过去多久、距本轮参考截止剩余/逾期或官方确认提前量。当前时间来自设备不代表数据最新，更不代表送达成功。生产接口应返回 serverTime 与最后成功核验时间；前端展示时钟校准状态，设备时钟偏差超阈值时提示。

翻页只切换帖子，不回滚整轮状态。已完成时翻到旧预告仍显示整轮已完成，不再次催额度。首次宣布、时间承诺、开始传播、官方完成、个人到账分别记录。个人到账无账户证据始终未知。

## 状态矩阵

| 事件状态 | 截止区域 | 行动文案 |
|---|---|---|
| 有可信预告与截止 | 参考截止 + 可能提前 | 安排已明确的重要工作 |
| 已宣布但无截止 | 未知 | 不制造倒计时 |
| 传播中 | 可保留参考上界；不保证可继续用旧额度 | 核验官方进度和自己可见用量 |
| 官方完成 | 官方确认发帖时间 + 相对截止提前/延后 | 停止催旧额度 |
| 截止已过、无确认 | 已过多久 + 完成未知 | 核验来源，不按倒计时归零判完成 |
| Banked | 资格、有效期及到账阶段 | 不直接套用 Global 的旧额度催促 |
| 定向补偿 | 适用范围与补偿阶段 | 不标题化为全员 Reset |
| 数据源失败 | 最近成功核验/故障/未知 | 不伪装没有新事件 |
| 无新事件 | 无新可信状态 | 静默，不推营销通知 |

## 各平台的设计重点与验收

微信小程序：预留胶囊、访客先读、订阅授权前解释用途；不能因为访问首页就请求所有权限。公众号文章只能发布静态内容，互动翻页/动态时间引导到真正支持脚本的产品页面。微信文档本次访问受限，授权细节在集成前重新核对，未宣称已通过微信审核。

iOS：分组信息、稳定 Tab 导航、安全区域与可读的正文；控制层可探索平台材质但不牺牲内容对比。Dynamic Type、VoiceOver、系统分享、通知授权、Widget/Live Activity 必须分别真机验收。原型的圆角外框和状态栏不是原生认证。

Android：清晰色调层次、48dp 目标触达、后退导航、TalkBack、权限与通知渠道；平板可迁为导航栏/侧栏加详情。省电限制、渠道接受与设备实际送达分别展示，不保证所有厂商后台一致。

HarmonyOS：单独验证 ArkUI/DevEco、导航栈、系统字号、安全区域、多窗口与折叠屏，不能把 APK 改名。元服务卡片与实况窗是未来触达概念，需平台适配与能力审核，不能由浏览器 UI 直接等价实现。

共同需要：离线、空、加载、权限拒绝、部分成功、失败、数据过期、撤销订阅、账号注销/数据管理。原型直接展示九种事件状态；网络请求、真实授权、注销与迁移不是本目录已经实现的业务。

## 未来产品界面

### 阶段 A：可靠提醒

先完成可信公告→事件关联→北京时间→紧急告警→服务商/设备可用回执→故障恢复。设计验收以“用户在能行动时看到可信信息”为核心，不用发送次数装作效果指标。

### 阶段 B：使用安排

探索原生小组件、历史对比、事件收藏、用户自愿的任务清单与提醒规则。没有官方账户接口时不偷偷抓取私有额度；可选择单独标注的手动记录。完成窗口提醒不以样本平均值预测下一次重置。

### 阶段 C：多来源与团队

多来源选择器、团队角色、Webhook、通知分工与审计。首页仍优先展示用户所关注的行动窗口；不能变成不分类的 AI 新闻流。其他服务需各自的权威证据与规则；商业套餐在需求验证后设计，不伪造价格、付费用户量或上线时间。

可跟踪的未来指标：公告到发现、发现到入队、入队到服务商接受、可用的设备回执时间、重复率与错误率。必须展示样本量和未知项；无法获得的阅读时间不能填 0。

## 交付映射与实现顺序

1. 将 token 与共用卡片规则沉淀到共享源；Web 与客户端由同一状态模型驱动。
2. 先实现 W01/W02 和移动动态/历史，保持既有 API 兼容。
3. W03/提醒页接入真实偏好、平台授权、通道健康与回执，完成小规模真机验证。
4. W04 继续保留告警与传播稿独立；公开发布必须有显式动作与审计。
5. 未来页中的小组件/团队/其他服务保留“规划”标签，满足门槛后再接通。

以上是技术依赖次序，不是按季度承诺交付日期，也不要求为每个平台重写整套产品。
